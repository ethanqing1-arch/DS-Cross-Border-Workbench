# brief-21：证据分层打分（让真实数据能出结论）

## 背景（全部是实测）

现在 `score_products.py` 用 6 个必需列一刀切：`1688进价 / 运费 / 平均退货率 / 月搜索量 / 在售竞品数 / 头部评论数`，缺任何一个直接 `补数据`、不参与打分。

但现实里能拿到的只有一部分：

- **Amazon 搜索页**（会抖动，503 频繁但能通）：价格带、评分、评论数、广告密度、搜索结果总数
- **Amazon 商品页**（抖动更厉害）：上架月龄、FBA、卖家（产品页 10 个里 10 个 503 是常态）
- **AliExpress 美国区**（稳定）：货源价、折扣、销量
- **拿不到**：`1688进价`（要采购账号）、`月搜索量`（要 ABA / 卖家精灵，仓库里只有 manifest 提到没有适配器）、`平均退货率`（要卖家后台）、`运费`

所以真实数据跑出来的永远是这一行：

```
1 | pet slow feede |  |  |  |  | 补数据 | [D] 缺失：1688进价、运费、平均退货率、月搜索量、在售竞品数、头部评论数
```

客户付钱装上，拿到的是「缺什么」清单，不是「能不能做」。**这一单就是把打分模型改成「用现有证据分级出结论」**，同时**不许把 brief-17 修掉的那个安全闸重新打开**。

## 核心设计：证据分层打分

### 1. 四维的输入放宽，但每一维单独判「能不能算」

| 维度 | 权重 | 一级输入（实测） | 二级输入（实测替代） | 都不能算时 |
|---|---|---|---|---|
| 需求 | 25% | `月搜索量` | `搜索结果总数` + `广告密度` | 该维 NA |
| 竞争 | 25% | `在售竞品数` + `头部评论数` | `评论数中位数` + `评论数>1000占比` + `评分中位数` | 该维 NA |
| 利润 | 30% | `预估售价` + `1688进价` + `运费` + `平均退货率` | **无替代**（利润不许猜） | 该维 NA |
| 风险 | 20% | `平均退货率` + `供应稳定性分` | `上架月龄中位数` + `FBA占比` | 该维 NA |

- 权重要按**可算维度重新归一化**，不要让缺失维度按 0 分计入（这是 brief-17 那条修复的精神）。
- 每行必须输出新列：`证据等级`（A/B/C/D）、`可算维度`（如 `2/4`）、`缺口`（缺了哪几维、缺的原因）。

### 2. 结论上限被证据覆盖度卡死（最关键的规则）

| 可算维度 | 利润可算 | 最高结论 |
|---|---|---|
| < 2 | — | `补数据` |
| 2–3 | 否 | `小批量观察` |
| 2–3 | 是 | `小批量观察` |
| 4 | **否** | `小批量观察`（诊断必须含「利润未验」，`红线` 列写「利润未验」） |
| 4 | 是 | `上架测试`（且无红线） |

`放弃` 不受上限影响，任何覆盖度都可以出。

### 3. 证据等级怎么给

- `A`：四维全部由一级输入支撑
- `B`：至少一维用了二级实测输入，没有代理
- `C`：至少一维用了代理输入（`搜索结果总数` 代 `月搜索量` 属于代理）
- `D`：结论是 `补数据`

证据等级 **C 的行不得出 `上架测试`**（代理指标不够格撑正向决策）。
