# rollback-withdraw 规格草案

**功能定义为待用户确认的推断。** L1 清单将 `rollback-withdraw` 标为 `missing-source`，仓库插件说明提到消息撤销和回滚。本草案据此提出工作台会话内的撤回预览，以及对有记录的本地变更进行恢复的流程。[L1 插件清单](../../distribution/l1/plugins/manifest.json) · [插件说明](../plugins.md)

## 要解决的问题

用户误发消息或误确认一次工作台变更时，需要先看到受影响的内容，再按权限撤回消息或恢复工作台状态。草案中的「撤回」是将目标消息标记为撤回并更新可见状态，「回滚」是将有快照且可恢复的本地变更还原到指定检查点。两种动作分别确认，预览列出后续消息与任务受影响的范围。

## 触发方式

- 有操作权限的用户从当前会话的消息或执行记录菜单打开撤回或回滚预览。预览无写入。
- 用户确认具体目标和影响范围后，由宿主调用执行接口。会话修订号变化、关联任务仍在运行、文件状态变化或检查点失效时，草案建议暂缓执行并重新预览。超时、关闭预览或生成失败均不得自行触发执行。

## 输入与输出

| 阶段 | 输入 | 输出 |
|---|---|---|
| 预览 | 工作区、会话、操作类型、消息或检查点 ID；调用者身份由宿主提供 | 预览 ID、基准修订号、受影响的消息和本地资源、当前不能处理的动作及原因 |
| 执行 | 预览 ID、基准修订号、用户确认与请求 ID | 结果状态、实际撤回或恢复的范围、未处理项、审计记录 ID |

预览必须将可恢复的本地变更、仍在运行的任务和已经发生的外部动作逐项呈现。执行时重新校验权限、修订号和资源版本；预览范围内有冲突时停止并回报原因。建议只对能原子提交的本地范围执行。同一请求 ID 的重试返回原有结果，失败需报告真实状态并保留原审计记录。

## 最小接口

```text
rollbackWithdraw.preview({workspaceId, sessionId, mode: withdraw | rollback,
                          targetId}) -> ImpactPreview
rollbackWithdraw.apply({previewId, expectedRevision, requestId}) -> ChangeResult
```

宿主把预览绑定到调用者、工作区和目标，并在收到用户明确确认后才调用 `apply`。两种模式的目标类型分别为消息 ID 和检查点 ID。可用的存储事务与检查点接口有待核对。

## 权限边界

- 读限定在当前用户获准处理的会话、关联执行元数据和本地资源版本。预览只显示用户原本可以查看的内容。
- 写限定在获批的消息撤回标记、已纳入管理且可核对版本的本地资源，以及追加式操作记录。恢复时保留后续人工修改，检测到并发改动则报告冲突。
- 不得删除审计历史、跨工作区回滚、覆盖未纳入管理的文件，也不得替用户发起电商平台订单、价格、库存或消息的补偿操作。已发生的外部动作仅在预览和结果中标明。

## 自检方式

在隔离测试工作区准备消息、带版本的本地变更、检查点和平台调用桩。

- 预览撤回和回滚后比较快照，确认预览无写入。执行后分别核对消息可见状态、恢复后的文件内容、后续消息状态和审计记录。
- 验证未确认、无权限、跨工作区、缺快照、预览过期、资源并发改动、任务仍在运行时执行被拦截，目标状态保持原样。
- 注入事务失败并重试同一请求，检查结果准确、无半完成状态及重复写入。含外部动作的场景应如实列出其状态，并确认平台调用桩的写操作计数为零。

## 实现前的待确认项

- 撤回覆盖本人消息还是也覆盖助手消息，支持哪些角色、共享可见性和时间窗口，撤回是全会话隐藏还是仅本地视图变化。
- 目标消息的后续回复、附件、下游分支和进行中的任务如何显示，是否允许先取消任务后重新预览，以及与 [retrace](retrace.md) 的交互。
- 首版回滚覆盖哪些工作区资源，如何生成检查点、定义事务边界、处理无快照和含外部副作用的混合场景。
- 是否允许恢复已撤回消息，提示与确认界面如何呈现，审计记录的内容、可见人和保留期。
- 接入宿主的消息权限、撤回标记、资源快照及并发控制接口。由用户确认采用原插件还是另行定义能力，并提供相应版本、源码、`package.json` 和 `LICENSE` 核对材料。
