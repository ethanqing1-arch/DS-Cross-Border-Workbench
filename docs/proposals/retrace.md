# retrace 规格草案

**功能定义为待用户确认的推断。** L1 清单将 `retrace` 标为 `missing-source`，仓库插件说明提到回溯、编辑重发和重新生成。本草案据此提出会话内回看与重试的流程。[L1 插件清单](../../distribution/l1/plugins/manifest.json) · [插件说明](../plugins.md)

## 要解决的问题

用户发现数字员工的回复偏离原意时，需要定位当时的输入和上下文，再从同一位置编辑输入或重新生成。建议把每次重试保存为从历史节点出发的新分支，保留原始对话和之后的消息，方便比较两次结果。

## 触发方式

- 能查看当前会话的用户从历史消息菜单打开「查看上下文」；可查看当时参与生成的可见消息及关联产物摘要。
- 具备会话编辑和模型调用权限的用户主动选择「编辑重发」或「重新生成」。编辑重发时先打开草稿，用户提交后才创建分支；重新生成时先展示将采用的历史输入与被排除的后续消息，用户确认后才创建分支。

## 输入与输出

| 操作 | 输入 | 输出 |
|---|---|---|
| 回看 | 工作区、会话、目标消息 ID；调用者身份由宿主提供 | 目标消息、可见上下文摘要、可用动作、会话修订号；历史缺失时标明缺失项 |
| 编辑重发 | 回看结果的会话修订号、目标用户消息 ID、编辑后的输入、请求 ID | 新分支与任务 ID、生成状态、最终回复或失败原因 |
| 重新生成 | 回看结果的会话修订号、目标助手消息 ID、请求 ID | 从目标回复所用的输入分支生成新回复，输出分支与任务 ID、生成状态及结果 |

重试的上下文以目标轮次为界。历史输入缺失、消息已撤回或回看后会话已变更时，返回原因并要求重新查看。一次确认对应一个请求 ID，重复提交返回已有任务。生成失败保留可见的失败状态，用户可主动再次重试。

## 最小接口

```text
retrace.inspect({workspaceId, sessionId, messageId}) -> ContextView
retrace.retry({workspaceId, sessionId, messageId, expectedRevision,
               mode: edit | regenerate, editedInput?, requestId}) -> RetryTask
```

`edit` 要求目标是用户消息且提供编辑后的输入。`regenerate` 要求目标是助手回复，由宿主解析其对应的用户输入。接口为概念签名，宿主的消息与分支接口有待核对。

## 权限边界

- 读限定在当前用户获准访问的工作区与会话，仅返回宿主允许显示的消息及关联产物摘要。隐藏提示词、密钥、隔离会话和已撤回内容不得通过回看或重试暴露。
- 写限定在用户确认后的新分支、对应生成任务和最小操作记录。模型生成沿用当前用户的模型权限。历史工具结果按当前可见性作为上下文，重试不得重放历史工具调用或触发新的工具写操作。
- 不得覆写原始会话、回滚关联产物、接触平台外部状态，或从日志和缓存拼回用户已经看不到的内容。

## 自检方式

在隔离的测试工作区用带工具结果的多轮会话和模型桩测试。

- 回看中间一轮，检查输出与目标轮次匹配、后续消息未进入重试上下文，并验证回看前后存储快照一致。
- 用同一目标分别编辑重发和重新生成，核对模型桩收到的输入与分支关系，确认原分支及产物完整，历史工具和写操作调用计数为零。
- 构造跨工作区访问、权限变化、已撤回消息、历史缺失、修订号过期、重复提交与生成失败。核对拒绝或失败原因，并验证同一请求最多创建一个任务。

## 实现前的待确认项

- 首版范围包含回看、编辑重发、重新生成中的哪些能力，哪些角色可用，个人和共享会话是否采用相同规则。
- 分支是否为正式会话能力，是否切换到新分支，原分支和失败任务如何显示、保留与审计。
- 哪些历史上下文字段可见，附件、工具结果、已过期依赖和已撤回消息如何处理。
- 重试用原模型配置还是当前配置，是否允许任何只读工具，模型调用费用如何提示。
- 与 [rollback-withdraw](rollback-withdraw.md) 的状态联动、界面入口和相同目标上的优先级。
- 接入宿主的事件、会话存储、分支与生成接口。由用户确认采用原插件还是另行定义能力，并提供相应版本、源码、`package.json` 和 `LICENSE` 核对材料。
