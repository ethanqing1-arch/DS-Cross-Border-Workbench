# Camoufox 常驻 worker 设计

当前每次体检由 `farm.js` 启动一个 Python 进程，每次 Camoufox 任务由网关启动另一个。两条路径都会启动 Firefox、打开账号 profile，再在请求结束后退出。创建会话含首检的交接实测约 8 秒。这个数字用于记录现状，性能验收重新采样。

## 进程归属与调用路径

每台宿主的 control 管理本机 Camoufox 进程。池按完整会话账号索引，并把规范化的 profile 路径绑定到 worker。control 从本地注册信息解析 profile、时区、语言和代理。网关传递账号、任务和截止时间，使用会话所在 control 执行任务。网关继续负责 REST 鉴权、限流、任务 ID 及结果查询。

将 `farm.js` 的 `runWorker` 和网关的 `runWorkerTask` 收敛到一个内部 worker 客户端，只有池有权启动 Python。将 Camoufox 体检结果的映射、指纹判定和台账记录提取成 CLI 和 control 可复用的逻辑。control 收到 Camoufox 体检请求时直接通过池提交 `scan`。`farm.js check` 走本地 control 的体检接口，保留现有参数、输出和退出码。需要支持无守护进程的 CLI 时，用同一个客户端开启命令生命周期内的池，并受相同的 profile 锁保护。遇到守护进程断线且持锁时返回账号忙，禁止回退到独立 spawn。

创建 Camoufox 会话时先登记账号。首检或第一个任务按需启动 worker。一个 worker 打开一个 persistent context，复用同一个任务页；`goto` 后的 `eval` 和 `shot` 因此访问同一页。控制面使用台账中的 `running` 状态判断逻辑会话是否存在，worker 空闲退出以后会话仍可用。更新启动配置前先排空并关闭上一代 worker。

## 协议与并发

stdin 和 stdout 使用 UTF-8 JSON Lines。stdout 仅保留协议帧，诊断写 stderr。启动成功后发 `{"event":"ready","protocol":1}`。任务帧包含 `id`、`type`、`params` 和可用执行预算。回复使用同一个 `id`，携带 `result` 或 `error:{code,message,detail?}`。关闭使用独立的 shutdown 帧。客户端检查协议版本、帧尺寸、ID 和消息形状，对未知响应 ID、非法帧及管道断开报告 `E_WORKER_NO_OUTPUT`。结果仍由现有 REST 任务状态包装。配置经受限的启动 IPC 传入，凭据从环境读取，日志仅包含账号、任务 ID、状态、时长和脱敏诊断。

同账号按 FIFO 串行执行，首检、显式 `scan` 和普通任务共享一条队列。对不同账号设全局启动和并行数量上限，对单个账号设队列上限。每个任务的预算包含排队、启动和执行。排队超时直接移出，执行超时返回 `E_TIMEOUT`，停止该 worker 并在回收完成后再处理剩余任务。进程异常退出时，当前任务失败，未派发任务可以在新一代按原截止时间继续。自动重放仅限尚未派发的任务，已派发任务可能已经改变页面或外部状态。连续启动失败采用有上限的退避，耗尽尝试后返回 `E_ENGINE_UNAVAILABLE`。

## 退出与 profile 保护

- **空闲。** 默认 5 分钟，可配置。队列为空且没有在途任务才开始计时。到期后关闭浏览器上下文，再退出 Python，账号保持可用。新的任务等待旧进程组退出后再启动下一代。
- **删除。** `DELETE /v1/sessions/:id` 由网关转给原 control。control 先把会话标记为正在关闭，拒绝新任务，取消排队任务，结束在途任务并回收进程组。确认 worker 和浏览器都退出后才应答和标记 stopped。保留账号台账、profile 和登录态。CLI 的 Camoufox stop 使用同一关闭路径。重复删除共享同一次回收。
- **网关退出。** 网关与每台 control 维持独立的内部租约，连接 EOF 触发释放，心跳过期兜底。独占于该租约的 worker 立即按关闭流程回收，关联的排队任务取消。共享会话只有在仍有有效租约时继续运行。重启的网关带新租约和代次重新登记。
- **control 或 Python 异常退出。** 在宿主上使用独立于 control 的轻量监护进程持有 profile 锁和 worker 的进程组。监护进程通过专用管道观察 control 的 EOF，同时监控 Python 的退出。正常关闭先通知 Python 关 context。到期向自己创建的进程组发送 SIGTERM，再按期限升级为 SIGKILL，等浏览器与 Playwright 驱动退出后释放锁。通过进程组验收确认受支持宿主上的所有子进程都归监护进程回收。
- **互斥与重启。** 按解析真实路径后的 profile 在宿主私有运行目录加 OS 排他锁，并在池内按账号合并并发启动。锁从启动前一直持有到进程组回收，浏览器原生 profile 锁作为最后一道保护。监护进程本身遭强杀时，通过记录的进程身份和代次核对残留，身份包括 PID 和启动时间。无法确认原浏览器已退出时拒绝启动，保留现场，避免复用 PID 导致误杀。迁移时，同一宿主先停止旧版的独立 worker 调用，再启用常驻路径，避免旧进程绕过锁。

## 实施后的验收

使用临时台账、profile 和备用网关/control 端口 `19971/19871`。固定一个本地静态 HTTP 页，创建 `require_check:false` 的 Camoufox 会话，连续提交三个 `goto`。每次从提交前计时到轮询确认 succeeded，记录每次耗时，并验证三个任务使用同一 worker 代次。多轮测量分别报告首次和后两次的中位数。建议热任务中位数低于冷启动的 50%，并校验紧随 `goto` 的 `eval` 能读取所到页面。

- 首检和同账号并发任务确认严格串行，不同账号确认隔离。执行超时后验证下一项换代运行，主动杀 worker 后验证在途任务失败且没有重放。
- 缩短测试空闲时间，验证回收后会话可重新冷启。删除时分别覆盖队列非空和任务在途，确认没有残余 Python、驱动或 Firefox，profile 保留。
- 在执行中分别终止备用网关和 control，覆盖 SIGTERM 与 SIGKILL。通过本次启动记录的 PID、启动时间和进程组确认无孤儿，再重启并确认可以重新打开同一 profile。
- 并行启动指向同一 profile 的两个调用，包括独立 CLI。验证只有一个获得锁，旧进程尚存时重启不会启动第二个写者。构造协议坏帧和启动失败，检查返回结构化错误并释放资源。
