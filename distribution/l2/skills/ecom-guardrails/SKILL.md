# 电商动作合规

## 什么时候用

在写商品页、做促销、管评价、处理投诉、发货或触达买家前，用这门 skill 判断拟做动作。动作已经发生时，先暂停重复执行，保留原文、平台通知、订单和操作时间等相关证据，再给整改步骤。向用户展示证据时遮盖买家个人信息。

## 三档判定

| 判定 | 怎么处理 |
| --- | --- |
| 禁做 | 停下这个做法，直接给能满足同一业务目标的替代动作。 |
| 需改造 | 指出哪段文案、流程或渠道需要改，给可用改稿或操作步骤，并列出执行前要核验的条件。 |
| 可做（有条件） | 逐项写出适用条件和核验结果。条件缺失时先补证据，核验完成后再由用户执行。 |

## 怎么查表

1. 确认平台、站点、目标、具体动作、触达渠道及激励或承诺。有现成文案时按原文判断，有投诉时先读平台通知和证据。
2. 打开 [动作合规对照表](references/action-compliance.md)，按动作匹配编号。一次操作命中多行时分别判断。对包含多个子场景的行，按实际做法及行内条件判定。
3. 给出判定、命中编号、风险如何发生、今天能做的下一步，以及需要在后台确认的条件。查不到对应行或条件未核实时，说明待确认项，给可先执行的低风险动作。

## 边界

- 本 skill 审核运营动作。侵权四查、认证、危险品、类目限制及 EPR/VAT 等商品准入问题，交由对应平台的准入合规流程处理。Amazon 使用 `compliance-gate`。
- 平台、站点与渠道的政策口径统一写「以卖家后台当期政策为准」。引用用户提供的后台内容时，概述适用要求，省略条款号、处罚金额和判例。
- 输出限于判断、草稿和人工执行步骤。涉及邀评、价格、否定词、发布和首帧的产品边界见对照表的「未实现项登记」。客服索评和差评处理先过本表，再拟回复。
