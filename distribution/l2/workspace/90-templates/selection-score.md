# 选品评分卡

一个候选 SKU 一张卡，存 `10-market/candidates/<候选ID>.md`。

**口径来源**：`decision-control`（技能）与 `95-engine/score.py`（引擎）。本文件与两处数字必须一致，改口径先改技能再改这里。
**通过线**：总分 ≥ 60 上架测试；48–59 观察；< 48 放弃。**红线优先于分数**，命中任一即 drop，分数再高也不进上架。

```yaml
candidate_id: US-KITCHEN-001-c1
title: 硅胶折叠沥水架
site: US
category: Home & Kitchen
source: 竞品ASIN反查 / 1688 / TikTok热榜
date: 2026-11-22
score_total: 0
verdict: pending        # pending | 上架测试 | 观察 | 放弃
sku_tier:               # 利润款 | 引流款 | 常规款 | 观察款 | 不做/清仓
redline_flags: PASS     # 如 R2|R3，全通过写 PASS
evidence_grade: B       # A 实测 / B 抓取 / C 估算 / D 假设
```

## 评分项（四维，满分 100）

| 维度 | 权重 | 原始值 → 0–100（绝对锚点，不用 min-max） |
|---|---|---|
| 需求强度 | 25% | `lin(log10(月搜索量), 3.0, 5.7)`：1k→0，500k→100 |
| 竞争压力 | 25% | `密度=lin(log10(竞品数),1,4)`；`壁垒=lin(log10(头部评论),1.5,5)`；`集中=top10_share×100`；得分 `= 100 − (0.5×密度+0.25×壁垒+0.25×集中)` |
| 盈利 | 30% | `0.5×lin(log1p(贡献利润),0,log1p(12)) + 0.3×min(100,贡献率/0.35×100) + 0.2×min(100,毛利率/0.80×100)` |
| 风险 | 20% | `30×(1−退货率) + 30×(供应稳定性/10) + 25×(差异化/10) + 15×(1−ip_risk/10)` |

`lin(v,a,b)=clamp((v-a)/(b-a)×100,0,100)`。总分 = Σ 维度分×权重，保留 1 位小数。

> 为什么不用 min-max：每批候选必然出现一个 100 分，跨批次与历史分数不可比。绝对锚点让 62 分在 3 月和 11 月是同一件事。

## 硬性红线（任一命中直接 drop，不计分）

| 编号 | 红线 | 判定线 |
|---|---|---|
| R1 | 毛利率不足 | 毛利率 < 30%（软线：降为观察，不 drop） |
| R2 | 贡献利润率不足 | < 8% |
| R3 | 单件贡献利润不足 | < 3 USD |
| R4 | 侵权/资质 | `ip_risk ≥ 7`，或 `cert_required=1` 且无资质（医疗器械、化妆品、食品、带电带锂电等） |
| R5 | 供应稳定性 | < 4/10（可稳定供货的供应商 < 2 家） |

D 级数据占比 > 30% 强制降档：最多只能给「观察」。

## SKU 分层（五档，一品只落一层）

| 层 | 规则 |
|---|---|
| 利润款 | 结论非放弃 且 贡献率 ≥ 20% |
| 引流款 | 结论非放弃 且 8% ≤ 贡献率 < 20% 且 需求分 ≥ 70 |
| 常规款 | 结论非放弃 且 不满足以上两条 |
| 观察款 | 总分 48–59 |
| 不做/清仓 | 总分 < 48 或命中 R2/R3/R4/R5 |

## 出分命令（唯一算法来源，禁止手算结论）

```bash
python3 ~/ds-bot-workspace/95-engine/score.py \
  --input 10-market/candidates/_scored/candidates.csv \
  --out   10-market/candidates/_scored
```

产出 `选品报告.md / 选品打分.csv / 决策卡.md / 选品看板.xlsx / run_meta.json`。
CSV 列名见 `95-engine/SKILL_SPEC.md` 第 4.6 节；报告首行必须是结论行（`结论：N 可做 / N 观察 / N 放弃（共 M 个候选）`）。

## 结论段（人工复核时只看这段）

```
结论：上架测试 / 观察 / 放弃
一句话理由：
最大风险：
红线：PASS 或 R1..R5 具体编号 + 触发值
下一步动作：询价 / 打样 / 放弃
```

## 已知反例（避免重复踩）

把每次 drop 的真正原因写进 `10-market/candidates/_rejects.md`，一行一条，格式：`候选ID | 原因（带 R 编号或分数） | 日期`。下次评分前先读这个文件。
