# 自定义 skill 创建器（6 问准入 → 骨架 → 3 case 回归 → 上线）

## 何时用

- 团队反复做同一件事，每次都要重新讲一遍要求。
- 有人问"这个能不能做成 skill"，需要给"做/不做"的判定而不是直接动手。
- 已有 skill 输出不稳、口径漂移，需要重建而不是打补丁。
- 新能力要进 router，需要一份符合规范的 `SKILL.md`。
- 上线前要证明"换了人跑也一样"。

不归这里：判断用哪个外部数据源/工具 → `toolchain-dispatch`；改某个已有 skill 的业务阈值 → 先回 `SKILL_SPEC.md` 第 4 节确认是否属于硬口径。

## 输入契约

| 字段 | 来源 | 缺失时怎么办 |
|---|---|---|
| `需求描述` | 用户口述/工单 | **必需**，压成一句"谁在什么场景下要什么结果" |
| `过去30天出现次数` | 工单/聊天记录/日历统计 | 缺失按 0 处理 → 直接不通过（宁可少写） |
| `输入字段清单` | 需求方给的表格/样例 | 缺失则先跑一次人工流程，把字段抄出来再回来 |
| `期望输出形态` | 文件 or 结构化块 | 缺失默认"落盘文件 + 正文结论" |
| `现有 skills 清单` | `skills/**/SKILL.md` | **必需**，用于查重（触发词与输出重叠） |

## 执行流程

1. **写一句定义**：`<谁> 在 <场景> 下要 <什么结果>`。写不成一句 → 需求太散，退回。
2. **跑 6 问准入闸**：按第 4 节逐条问，答"是/否 + 证据"，六问全记录进 `准入判定.md`。任一硬性条件不满足 → 输出"不写"，并说明改用什么（现有 skill / 一次性 prompt / 手工表）。
3. **查重**：`grep -ril "<核心动词>" skills/*/*/SKILL.md`，把触发词与输出的重叠处列出来；重叠 > 50% → 改为在已有 skill 里加一节，不新建。
4. **定骨架**：按 `SKILL_SPEC.md` 第 2 节写 frontmatter 与 7 个小节，一节不缺；`name` 用小写连字符、不带层前缀，全局唯一。
5. **填写小节**：`何时用` 3–5 条场景 + 1 条反例；`输入契约` 每行标"必需"或写清降级路径；`执行流程` 每步是可执行动作 + 取数口径；`判定口径` 全部给数字；`输出契约` 给落盘路径与字段清单；`质检清单` 5–8 条含数据可信度声明；`反模式` 3–5 条"错误 → 正确"。
6. **控制在 120–220 行**：超了就把长表搬到 `references/<topic>.md`，主文件只留引用与结论；短于 120 行说明判定口径不足，回去补阈值。
7. **跑 3 个 case**：取 3 个真实输入（含 1 个缺字段的边界 case、1 个不该触发的反例 case），逐个执行并记录"预期输出 / 实际输出 / 是否一致 / 差在哪"。
8. **修到 3/3 一致**：不一致时先看是判定口径缺数字，还是执行流程缺步骤；只改 skill，不改 case。
9. **过上线清单**：按第 4 节逐条勾（frontmatter 完整、行数区间、无占位符、上下游互链、触发词不撞车、版本号）。
10. **互链**：把本 skill 写进上游的 `downstream`、下游的 `upstream`，两边都要改，单向链接算不合格。
11. **落盘**：`准入判定.md`、`skills/<NN-layer>/<skill-name>/SKILL.md`、`回归记录.md`、`上线清单.md`。
12. **登记**：在 router 的 skill 索引里加一行（name + 触发词 + 层），并在 `versions` 记 1.0.0。

取数口径：出现次数按过去 30 天同一意图的去重次数计（同一天问 3 次算 1 次）；查重只看 `description` 的触发词与 `outputs` 的文件名，不看正文措辞。

## 判定口径

6 问准入闸（前三问与第 5 问是硬闸）：

| # | 问题 | 通过条件 | 不通过时 |
|---|---|---|---|
| 1 | 是否重复出现 ≥ 3 次（30 天内，去重） | 是 | 写成一次性 prompt，不建 skill |
| 2 | 是否有稳定输入（字段可枚举、缺失有降级路径） | 是 | 先人工跑 3 次，把字段抄出来 |
| 3 | 是否有可判定输出（有数字阈值或三态结论） | 是 | 补阈值，补不出来就不建 |
| 4 | 是否需要外部数据 | 是→必须写取数口径与失败降级；否→写"纯本地计算" | 未写降级路径 → 返工 |
| 5 | 是否已有 skill 覆盖（触发词或输出重叠 > 50%） | 无覆盖 | 在已有 skill 加一节，不新建 |
| 6 | 失败成本多高 | 中/高 → 建 SKILL.md；低 → 只写 `references/` 便签 | 低且高频 → 做成 checklist，不建 skill |

准入结论只有三个：`建 skill` / `加一节到 <已有 skill>` / `不建`。

查重与重叠度（决定"新建"还是"加一节"）：

| 重叠项 | 权重 | 判定 |
|---|---|---|
| `description` 触发词重合 ≥ 3 个 | 40% | 高 |
| `outputs` 文件名/交付物相同 | 30% | 高 |
| `执行流程` 前 3 步动作相同 | 20% | 中 |
| `判定口径` 阈值表相同 | 10% | 中 |

加权 ≥ 50% → "加一节到已有 skill"；< 50% 且有独立输入输出 → 新建。

行数预算（120–220 行的分配建议，防止某一节吃掉全文）：

| 小节 | 建议行数 | 下限 |
|---|---|---|
| frontmatter + 标题 | 12–14 | 10 |
| 何时用 | 8–12 | 6 |
| 输入契约 | 12–20 | 8 |
| 执行流程 | 20–40 | 15 |
| 判定口径 | 20–40 | 12 |
| 输出契约 | 12–20 | 8 |
| 质检清单 | 10–14 | 5 |
| 反模式 | 10–16 | 6 |

质量硬指标：

| 指标 | 阈值 | 校验方式 |
|---|---|---|
| 主文件行数 | 120–220 | `wc -l` |
| 小节数 | 7 个，一节不缺 | 逐个 `grep '^## '` |
| frontmatter 字段 | `name/description/layer/version/inputs/outputs/upstream/downstream` 全有 | 头部 10 行内检查 |
| 判定口径数字 | ≥ 5 个带单位的阈值 | 人工数表行 |
| 占位符 | 三类占位符（模式见 `references/admission-gate.md` 第 4 节）出现 0 次 | `grep -nE 'T[O]DO|x{3}|待[补]充'` |
| 回归 case | 3/3 一致 | `回归记录.md` |

## 输出契约

- 落盘：`out/<run_id>/准入判定.md`、`skills/<NN-layer>/<skill-name>/SKILL.md`、`out/<run_id>/回归记录.md`、`out/<run_id>/上线清单.md`
- `准入判定.md` 必须含：6 问逐条答案 + 证据 + 结论三选一 + 若"不建"的替代方案。
- `回归记录.md` 表格列：`case_id, 输入摘要, 预期结论, 实际结论, 一致?, 差异点, 修的哪一节`。
- `上线清单.md` 表格列：`检查项, 阈值, 实测, 通过?`。
- 正文格式：先给准入结论（建/加一节/不建 + 一句理由）→ 6 问表 → 回归结果 → 上线清单。结论后标 `[A]`/`[B]`/`[C]`/`[D]`。

## 质检清单

- [ ] 6 问逐条有答案与证据，没有"大概""应该"。
- [ ] 查重跑过 `skills/*/*/SKILL.md`，重叠比例写出来了。
- [ ] frontmatter 8 个字段齐全，`name` 全局唯一且不带层前缀。
- [ ] 7 个小节齐全，顺序与 SPEC 第 2 节一致。
- [ ] 主文件 120–220 行，长表已外链到 `references/`。
- [ ] 判定口径至少 5 个带单位阈值，没有"较高/偏低/适中"。
- [ ] 3 个 case 全过，其中 1 个缺字段、1 个反例。
- [ ] 上下游互链双向改过；占位符扫描 0 命中；数据可信度声明已写。
- [ ] 行数预算按小节分配过，没有单节占比超过 35%。
- [ ] 查重加权重叠度已算，落在"新建"而不是硬塞。

## 反模式

- 有人提一次就建 skill。→ 错：先过第 1 问（30 天内 ≥ 3 次去重），否则写 prompt。
- 把长表格塞进主文件凑行数。→ 错：主文件只留判定结论与引用，细节进 `references/`。
- 判定口径写"视情况而定"。→ 错：必须给数字阈值；给不出说明业务没想清，不建。
- 只有 1 个 case 跑通就上线。→ 错：必须 3 个，且含缺字段的边界与不该触发的反例。
- 只改下游的 `upstream`，不改上游的 `downstream`。→ 错：单向链接会让 router 路由不到，两边都要改。
- 为了凑 120 行把同一句话换三种说法。→ 错：行数下限是为了装下阈值，不是为了字数；写不出阈值说明还不该建。
