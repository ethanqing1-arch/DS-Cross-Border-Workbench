# 水军判定规则与抽样核验

本文件是 `amz-review-harvest` 步骤 6、7、10 的执行细则。所有规则必须输出命中条数与命中 ID，不允许只给一个「水军率」。

## 1. 三条硬规则

### R1 同句式（模板刷单）

- 计算：同 ASIN 内两两评论正文的 5-gram shingle Jaccard 相似度。
- 命中条件（同时满足）：
  1. 相似度 ≥0.90 的评论 ≥3 条；
  2. 这 ≥3 条发布日期落在 7 天窗口内；
  3. 星级相同。
- 输出：`spam_rule=R1`，同组写 `spam_group=<组号>`。
- 常见模板（类目词典，需按 `category` 扩充）：
  - `game changer` / `life changing` / `exceeded my expectations` / `highly recommend` / `five stars` / `works great` / `exactly as described`
  - 上述短语单独成句且正文 ≤15 词 → 提高优先级，人工复核。

### R2 集中时段（冲量）

- 计算：同 ASIN 按 `review_date` 排序，滑动 48 小时窗口内的 5 星评论数。
- 命中条件（同时满足）：
  1. 窗口内 5 星 ≥15 条；
  2. 窗口内 `verified_purchase=0` 占比 ≥80%。
- 输出：`spam_rule=R2`，记窗口起止日期。
- 注意：真实爆款在 Prime Day 后 48 小时也可能出现 15+ 条五星，但 VP 占比通常 >85%。VP 占比是判别关键。

### R3 无 VP + 极短

- 命中条件（同时满足）：
  1. `verified_purchase=0`；
  2. 正文词数 ≤12；
  3. `rating=5`；
  4. 该 ASIN 中满足 1–3 的评论占比 >25%。
- 输出：`spam_rule=R3`。
- 单独一条 R3 特征不算水军（真实用户也会写短评），必须过 25% 占比阈值。

## 2. 软信号（只标记，不判水军）

| 信号 | 判定 | 字段 |
|---|---|---|
| 测评/免费样品 | 含 `received this product for free`、`in exchange for`、`sent me this`、`Vine Customer Review` | `incentivized=1` |
| 图片齐全但文本空洞 | `has_image=1` 且词数 ≤15 且评分 =5 | `low_info=1` |
| 帮助票异常高 | `helpful_votes` > 该 ASIN 中位数 ×10 且评论 <30 词 | `vote_anomaly=1` |
| 同一评论者跨 ASIN | 页面显示同一 profile 名在 ≥3 个目标 ASIN 留评 | `repeat_reviewer=1` |

软信号不剔除，但在 `voc-mining` 做情感加权时 ×0.5。

## 3. 判定顺序与冲突

1. 先跑去重（步骤 6），重复组先剔除，避免同一段文本既算重复又算水军。
2. 再跑 R1 → R2 → R3，一条评论只记第一个命中的规则号。
3. 软信号最后打，可与硬规则叠加。
4. `spam_flag=1` 的行全部移入 `reviews_raw.csv`，`reviews.csv` 不含。

## 4. 抽样核验（步骤 10）

### 4.1 人工抽检 50 条

按 ASIN 分层随机抽（每 ASIN 至少 2 条），逐条核对：

| 核对项 | 通过标准 |
|---|---|
| 星级 | 与页面星标一致 |
| 日期 | 与页面日期一致，误差 0 天 |
| VP | 页面有 `Verified Purchase` 即 1 |
| 帮助票 | 与页面数字一致（页面会实时变，允许 ±2） |
| 变体 | 与页面 `Color/Size` 原文一致 |

任一项错 >2 条 → 该字段整列重抓。

### 4.2 星级分布校验

抓取分布（分析集，按条数）与页面直方图（按百分比）对比：

`偏差_i = |抓取占比_i − 页面占比_i|`，i = 1..5 星。

- 全部 ≤3 个百分点 → 通过。
- 任一 >3 个百分点 → 说明抽样有偏（多半是翻页没到 12 个月下界，或排序不是 `Most recent`），回到步骤 3 重抓。

### 4.3 时间分布校验

近 12 个月按月统计条数，若某月条数为 0 但前后月均 >20 条 → 检查是否翻页中断（亚马逊分页偶发丢页），补抓该月。

## 5. 输出字段对照

| 字段 | 取值 | 进哪个文件 |
|---|---|---|
| `spam_flag` | 0/1 | 两个文件都有 |
| `spam_rule` | R1/R2/R3/空 | 两个文件都有 |
| `spam_group` | 组号/空 | raw 为主 |
| `incentivized` | 0/1 | 两个文件都有 |
| `low_info` / `vote_anomaly` / `repeat_reviewer` | 0/1 | 两个文件都有 |
| `dup_group` | 组号/空 | 两个文件都有 |

## 6. 反例校准（用真实量级判断阈值是否合理）

- 一个 4000 条评论的老品，近 12 个月 900 条，R1 命中 12 条（1.3%）、R2 命中 0 条 → 正常。
- 一个上架 3 个月的新品，320 条评论，R2 命中 96 条（30%）、VP 占比 41% → 判定刷单，该 ASIN 的 4.8 分不可信，只能做定性参考。
- 一个 4.1 分产品，1 星占比 22%，R1/R2/R3 全 0 → 真实产品缺陷，正是 VOC 要挖的对象，不要误删。
